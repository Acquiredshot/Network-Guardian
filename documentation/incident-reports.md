# Threat Reports & Incident Reports

Network Guardian automatically generates two structured documents on every threat detection cycle: a machine-readable **ThreatReport** and a human-readable **Markdown Incident Report**.

---

## Overview

| Document | Format | Generated by | Stored at | Dashboard page |
|---|---|---|---|---|
| `ThreatReport` | JSON (dataclass) | `ProbeReActAgent.run_cycle()` | Fleet store, per-agent | `/reports` |
| Incident Report | Markdown (prose) | `_generate_incident_report_md()` | Disk + fleet store | `/incidents` |

Both documents are generated **automatically** — no user action required. Every threat detection (and every 10 clean cycles for baseline reports) triggers the full pipeline.

---

## ThreatReport (JSON)

Defined in `network_guardian/agent/react_agent.py` as a `@dataclass`.

### Fields

| Field | Type | Description |
|---|---|---|
| `report_id` | `str` | UUID — unique identifier for this report |
| `generated_at` | `str` | ISO 8601 UTC timestamp |
| `agent_id` | `str` | Probe identity (e.g. `NG-608852BB`) |
| `host` | `str` | Hostname of the agent machine |
| `cycle` | `int` | ReAct cycle number since agent start |
| `risk_level` | `str` | `critical`, `high`, `medium`, `low`, `clean` |
| `threat_score` | `float` | 0–100 composite risk score |
| `threats` | `list[dict]` | Each detected threat (see below) |
| `actions_taken` | `list[dict]` | Local remediation actions applied |
| `observations` | `dict` | Key stats: connections, processes, ports, external endpoints |
| `baselines` | `dict` | Drift percentages from established baselines |
| `narrative` | `str` | Plain-English explanation of the full cycle |
| `recommendations` | `list[str]` | Prioritised response steps |

### Per-threat entry

```json
{
  "threat_type": "arp_spoof",
  "severity": "high",
  "description": "ARP spoofing detected — gateway MAC changed",
  "what": "ARP spoofing is a man-in-the-middle attack...",
  "impact": "The attacker can read or modify all network traffic...",
  "why_triggered": "MAC address recorded for a known IP changed between cycles.",
  "cvss_base": "8.1 (High)",
  "mitre": "T1557.002 — ARP Cache Poisoning",
  "affected_items": ["192.168.1.1"],
  "remediation": "...",
  "immediate_steps": ["Disconnect from the network", "..."],
  "long_term_steps": ["Enable Dynamic ARP Inspection", "..."]
}
```

### Threat categories

| Threat type | MITRE ATT&CK | CVSS Base |
|---|---|---|
| `arp_spoof` | T1557.002 — ARP Cache Poisoning | 8.1 (High) |
| `rogue_process` | T1059 / T1106 | 7.5 (High) |
| `port_scan` | T1046 — Network Service Discovery | 5.3 (Medium) |
| `data_exfil` | T1041 — Exfiltration Over C2 Channel | 8.8 (High) |
| `anomaly` | T1071 — Application Layer Protocol | 6.5 (Medium) |

### Accessing via API

```
GET /api/fleet/reports               → all ThreatReports from all agents
GET /api/fleet/agent/<id>/reports    → ThreatReports for one agent
```

## Markdown Incident Report

A prose narrative saved as a `.md` file. Follows the same format as `INCIDENT_REPORT_2026-04-13.md`.

### Filename format

```
INCIDENT_REPORT_YYYY-MM-DD_<report_id>.md
```

Example: `INCIDENT_REPORT_2026-04-26_a3f7c821.md`

### Storage locations

Reports are saved to **two locations** on every detection:

1. **Agent data dir:** `~/.ng_agent/incident_reports/`
2. **Project directory:** `./incident_reports/` (next to the codebase)

If a location is not writable, it is skipped silently.

### Report structure

```markdown
# INCIDENT REPORT — YYYY-MM-DD HH:MM UTC

**Agent:** NG-XXXX  
**Host:** hostname  
**Risk Level:** HIGH  
**Threat Score:** 72.5/100  
**Report ID:** a3f7c821  

---

## Executive Summary
Plain-English narrative of what was observed, what it means,
and the recommended response.

---

## Threats Detected

### 1. ARP_SPOOF — HIGH
**What is this?** ...
**What is the impact?** ...
**Why was this triggered?** ...
**CVSS Base Score:** 8.1 (High)
**MITRE ATT&CK:** T1557.002 — ARP Cache Poisoning

**Affected items:**
- 192.168.1.1

**Immediate response steps:**
1. Disconnect from the network
2. ...

**Long-term hardening:**
1. Enable Dynamic ARP Inspection on managed switches
2. ...

---

## Observations at Time of Detection
| Metric | Value |
|---|---|
| Active connections | 47 |
| External connections | 12 |
| Listening ports | 15 |
| Active processes | 122 |
| Network baseline drift | 18.5% |
| Process baseline drift | 4.2% |

---

- Logged threat event to fleet store
- Emitted alert to dashboard event feed

---

## Recommendations
1. Immediately investigate ARP table on all network devices
2. ...
```

### Accessing via dashboard

```
GET /api/fleet/incidents                 → all Markdown incident reports
GET /api/fleet/agent/<id>/incidents      → reports for one agent
```

The `/incidents` dashboard page renders reports as inline Markdown and provides a `.md` download button for each.

---

## Transmission to Dashboard

When the agent phones home, `incident_report_md` is embedded in the fleet report payload:

```json
{
  "agent_id": "NG-XXXX",
  "threat_reports": [ { ...ThreatReport... } ],
  "incident_report_md": "# INCIDENT REPORT — ..."
}
```

The fleet store saves both documents separately so they can be queried independently.

---

## Generation trigger

| Condition | What is generated |
|---|---|
| Any threat detected in ReAct cycle | Full `ThreatReport` + Markdown incident report |
| 10 clean cycles with no threats | Baseline `ThreatReport` only (no incident report) |

Clean-cycle baseline reports feed the AI Engine's rolling time-series without polluting the incident log.
